## Transcript search index (B1)

Not committed as a migration, because it could not be tested against the
production database: it needs the `pg_trgm` extension, and it builds a large
index (a trigram GIN over every transcript line). Check free disk on the Xata
branch first. Try it on a Xata validation branch, then run each statement on
its own against `DIRECT_URL` (for example with `psql`), outside a transaction:

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;
CREATE INDEX CONCURRENTLY IF NOT EXISTS "TranscriptSegment_text_trgm_idx"
  ON "TranscriptSegment" USING gin ("text" gin_trgm_ops);
```

If the build is interrupted it leaves an invalid index: drop it
(`DROP INDEX CONCURRENTLY "TranscriptSegment_text_trgm_idx"`) and run it again.
Once it is valid, `ILIKE '%q%'` uses it for queries of three characters or
more with no code change. Once it has worked there, commit the two statements
as migrations (one statement per file, like `20260930000002`) so a new
database gets the index too.
