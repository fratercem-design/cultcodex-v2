network policy blocks cultcodex.me, so the live site could not be fetched.

database (schema from `prisma db push`, data from `prisma/seed.ts`, TLS with

## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| R1 | **High** | **Admin pages leaked their data to signed-out visitors.** `src/app/admin/layout.tsx` redirects non-admins, but the App Router renders a layout and its page in parallel. 21 of 28 server-rendered admin pages had no check of their own, so their queries ran anyway and the rendered result streamed in the body of the 307. Confirmed locally: `curl /admin/users` returned user names and emails, `curl /admin/leads` returned subscriber emails, with no cookie. The same applied to comments, claps, episodes, people and the dashboard. `src/proxy.ts` does not gate `/admin`. | **Fixed.** New `requireAdminPage()` in `src/lib/auth.ts` redirects before any query runs. It is the first statement of every server-rendered admin page and of the layout. `src/app/admin/__tests__/admin-page-guard.test.ts` fails CI if an admin page skips it. Re-tested: every admin route returns a 307 with no data |
| R2 | Medium | **The inline server action on `/admin/signals` had no auth check.** It updated `SignalProposal.status` directly. Server actions are public POST endpoints, and R1 exposed their action IDs in the page payload, so anyone could change proposal statuses. Every other admin action delegates to a guarded function in `actions.ts` / `create-actions.ts`. | **Fixed.** The action now calls `requireAdmin()` |
| R3 | Medium | **The `/signal` share image crashed on any day with a quote.** The same bug is in `/api/signal/share-card`. Satori (next/og) rejects a non-flex `<div>` with several children, and `“{quote}”`, `#{date}` / `TX-{date}` and `EP.xxx · {title}` each produce several. Shared links to `/signal` got no preview image. It only showed with real data: the fallback text rendered fine. | **Fixed.** Each is now a single template-string child. All 35 image routes render |
| R4 | Info | `prisma migrate deploy` cannot build a fresh database: the first committed migration expects existing tables. This does not affect production, but a new environment has to use `prisma db push` or a restored dump. | Open — consider a baseline migration |

Still open from 2026-09-23: N5 (admin `GET` routes that write, and non-expiring HMAC keys), N6 (hard-coded clap coupon), N10 (stale Vercel wording), F5 (`force-dynamic` on archive templates).

## Recommended follow-up

1. Deploy this fix promptly (`fly deploy -a cultcodex-v2`; no migrations). R1 exposed user and subscriber emails to anyone who requested an admin URL.
2. Check Cloudflare or Fly logs for anonymous requests to `/admin/*` that got a 307 with a large body. Any such request since the admin pages were added is a possible disclosure.
3. Consider also gating `/admin` in `src/proxy.ts` (session-cookie check) as a second layer.
